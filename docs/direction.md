## 3. 문제 정의 (가설)

> 숙소 검색 필터(지역, 날짜, 인원 등)로 표현되지 않는 고객의 조건이 있다. 이런 조건은 **고객센터 문의나 이탈**로 이어지고, 결국 운영 부담이 된다.

- 예시 조건: "다음주 금토", "아이 둘이라 침대 따로", "강아지 동반 가능하고 욕조 있는 곳", "부산 바다 보이는 곳"
- 내부 데이터(문의량, 이탈률)는 없으므로 **가정이라고 명시**하고, 면접에서 검증할 질문으로 남긴다.

### 공개 사이트 관찰 결과 (2026-10-13, urbanstay.co.kr 웹)

| # | 관찰 | 근거 |
|---|---|---|
| 1 | 검색 입력은 **지역(8개 시도), 날짜, 인원** 세 가지뿐이다 | `evidence/01-home-search.jpg` |
| 2 | 검색 결과(지점 목록)에 **정렬이나 필터 UI가 없다**. URL 파라미터도 `regionId, checkIn, checkOut, guestCount`뿐이다 | `evidence/02-search-results.jpg` |
| 3 | 오션뷰, 스파, 욕조, 펫룸, 트윈, 커넥팅, 베리어프리, 로프트 같은 객실 속성은 **객실 이름에만 들어 있다** (예: "프리미어 스위트 패밀리 펫룸", "스튜디오 베리어프리"). 검색으로는 거를 수 없다 | 홈 큐레이션 목록, 지점 상세 |
| 4 | 반려동물 가능 여부, 영유아 인원 기준 같은 조건은 **지점 상세 > 이용 정책 > 접힌 아코디언** 안의 텍스트로만 안내된다 (로이움 지점: "반려동물 동반 입실 불가", "36개월 이하 영유아는 인원수 미포함") | `evidence/03-branch-policy-pet-infant.jpg` |
| 5 | 고객센터는 채널톡 채팅으로 연결된다. 조건을 확인하려는 고객이 문의할 수 있는 창구가 있다 | 페이지 리소스(`/apis/v1/channelTalk/member`) |
| 6 | 홈 큐레이션에서 이름에 "펫룸"이 들어간 객실은 1종(시흥 웨이브파크)만 보였다 | 홈 텍스트 |

**결론:** 가설의 전제(필터로 표현되지 않는 조건이 있다)는 확인됐다. 다만 이것이 실제로 문의나 이탈로 이어지는지는 확인할 수 없으므로 가정으로 남긴다.

### 설계에 주는 함의
- 목업 인벤토리의 객실 속성(뷰, 욕조, 스파, 펫, 트윈, 베리어프리, 방 개수)은 **실제 객실 이름에서 파생**해 만든다. 실제 데이터 모델을 흉내 내는 근거가 된다.
- 인원 해석 규칙이 필요하다: "어른 2명, 돌 아기 1명"은 인원 2명이다(36개월 이하 미포함). 평가셋에 포함한다.
- 펫 가능 객실이 매우 적으므로, 조건을 만족하는 결과가 없을 때의 응답(대안 제시, 조건 완화 제안)이 실제로 자주 필요한 기능이다.
- 지점별 정책(펫, 주차, 조식)과 객실 속성을 구분해서 모델링한다.

## 4. 설계 원칙

```
자연어 입력 → LLM이 구조화된 검색 조건(JSON) 추출 → 코드로 목업 인벤토리 검색 → 결과 제시 → 사용자 확인
```

- **AI는 의도 해석만 맡는다.** 객실, 재고, 가격은 결정적 로직과 데이터에서만 나온다. LLM이 방이나 가격을 생성하지 않는다.
- **모호하면 되묻는다.** 날짜 상대 표현, 인원 누락 등은 추측하지 않고 질문한다. 평가셋에 "되묻는 것이 정답"인 케이스를 포함한다.
- **예약 확정 직전에 멈춘다.** 조건 요약과 후보 객실을 보여주고 사용자가 확인하는 단계까지만 구현한다.
- **멀티모달은 기본 범위에서 제외한다.** 이미지 입력이 꼭 필요한 실제 상황이 설득될 때만 확장 기능 하나로 추가한다. 넣지 않으면 README에 "검토했지만 뺀 이유"를 적는다.

## 5. 범위

**포함**
- 목업 인벤토리: 공개 정보(지점, 객실 유형, 옵션) 기반. 가격과 재고는 가짜 데이터라고 명시한다
- 조건 추출: LLM structured output, 스키마 검증 포함
- 검색 로직과 대화 UI(되묻기, 확인 단계)
- 평가셋(30~50개)과 평가 스크립트, 프롬프트 버전별 정확도 기록
- 배포 URL(Vercel)

**제외** (README에 의도적 제외로 명시)
- 결제, 실제 예약 확정, 인증
- 실제 PMS·채널 매니저 연동
- 다국어

## 6. 평가 계획

- **구현보다 평가셋을 먼저 만든다.**
- 케이스 형식: `입력 문장`, `기준 날짜`, `정답 조건 JSON` 또는 `되물어야 할 항목`
- 지표: 필드별 정확도, 되묻기 정확도(물어야 할 때 묻고, 안 물어도 될 때 안 묻는지)
- 프롬프트나 스키마를 바꿀 때마다 수치와 실패 유형을 `docs/ai-log.md`에 기록한다
