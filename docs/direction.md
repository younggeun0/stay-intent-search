## 3. 문제 정의 (가설)

> 숙소 검색 필터(지역, 날짜, 인원 등)로 표현되지 않는 고객의 조건이 있다. 이런 조건은 **고객센터 문의나 이탈**로 이어지고, 결국 운영 부담이 된다.

- 예시 조건: "다음주 금토", "아이 둘이라 침대 따로", "강아지 동반 가능하고 욕조 있는 곳", "부산 바다 보이는 곳"
- 내부 데이터(문의량, 이탈률)는 없으므로 **가정이라고 명시**하고, 면접에서 검증할 질문으로 남긴다.

| # | 관찰 | 근거 |

**결론:** 가설의 전제(필터로 표현되지 않는 조건이 있다)는 확인됐다. 특히 **사양 데이터는 이미 정형화되어 있는데 검색에 쓰이지 않는다**(3a, 3c)는 점은 구현 비용이 낮은 개선 여지라는 근거가 된다. 다만 이것이 실제로 문의나 이탈로 이어지는지는 확인할 수 없으므로 가정으로 남긴다.

### 설계에 주는 함의
- 목업 인벤토리는 두 층으로 만든다.
  - **정형 사양**(3a): 상세 창 필드를 그대로 따른다(인원, 크기, 침실 수, 침대 구성, 욕실 수, 시설 태그).
  - **이름 기반 속성**(3b): 전망, 펫, 스파, 욕조, 트윈 등은 객실 이름에서 파생한다.
- 침대 구성이 정형 데이터로 있으므로 "아이 둘이라 침대 따로" 같은 조건을 실제로 처리할 수 있다. 평가셋에 포함한다.
- 인원 해석 규칙이 필요하다: "어른 2명, 돌 아기 1명"은 인원 2명이다(36개월 이하 미포함). 평가셋에 포함한다.
- 펫 가능 객실이 매우 적으므로, 조건을 만족하는 결과가 없을 때의 응답(대안 제시, 조건 완화 제안)이 실제로 자주 필요한 기능이다.
- 지점별 정책(펫, 주차, 조식)과 객실 속성을 구분해서 모델링한다.

## 4. 설계 원칙

```
자연어 입력 → LLM이 구조화된 검색 조건(JSON) 추출 → 코드로 목업 인벤토리 검색 → 결과 제시 → 사용자 확인
```

- **AI는 의도 해석만 맡는다.** 객실, 재고, 가격은 결정적 로직과 데이터에서만 나온다. LLM이 방이나 가격을 생성하지 않는다.
- **모호하면 되묻는다.** 날짜 상대 표현, 인원 누락 등은 추측하지 않고 질문한다. 평가셋에 "되묻는 것이 정답"인 케이스를 포함한다.
- **예약 확정 직전에 멈춘다.** 조건 요약과 후보 객실을 보여주고 사용자가 확인하는 단계까지만 구현한다.
- **멀티모달은 기본 범위에서 제외한다.** 이미지 입력이 꼭 필요한 실제 상황이 설득될 때만 확장 기능 하나로 추가한다. 넣지 않으면 README에 "검토했지만 뺀 이유"를 적는다.

## 9. 확장 방향 (과제 범위 밖, README "다음 단계"에 쓸 내용)

목업 인벤토리는 PMS에 접근할 수 없어서 만든 대체물이다. **LLM이 만드는 조건 JSON은 그대로 두고 검색하는 데이터 소스만 바꾸는 구조**로 만들어, 교체 지점을 README에 명시한다.

```
자연어 → LLM이 조건 JSON 추출 → [지금] 목업 배열 필터
                              → [PMS 연동 후] DB 쿼리 + PMS 재고/요금 API
```

### 벡터 검색을 주 검색으로 쓰지 않는 이유
- 펫 가능, 인원, 방 개수, 날짜별 재고, 가격은 **정확히 맞아야 하는 조건**이다. 유사도 검색은 펫 불가 객실을 "비슷하다"는 이유로 섞을 수 있고, 예약에서는 이런 오답이 곧 클레임이 된다.
- 재고와 가격은 실시간 값이라 임베딩으로 표현할 수 없다.

### 벡터 검색이 맞는 곳 (하이브리드)
정형 필터로 후보를 거른 뒤, 정형화되지 않은 텍스트에만 쓴다.
- **정책·공지 질의응답(RAG):** "주차 되나요?", "얼리 체크인 돼요?"를 지점별 이용 정책 텍스트에서 찾아 답한다.
- **분위기·취향 순위:** "조용한 곳", "아이랑 놀기 좋은 곳"을 객실 설명이나 리뷰 유사도로 정렬한다.

### 면접에서 확인할 질문
- 상세 창의 사양과 시설 태그는 정형 데이터로 보인다. 이것이 PMS의 필드인지, 별도 콘텐츠 관리 데이터인지?
- 전망, 펫 동반, 욕조처럼 **이름에만 있는 속성**은 내부에서도 이름 문자열뿐인지? 그렇다면 "객실 이름 → 속성 태그 정규화"가 먼저 필요하고, 이것도 LLM 추출과 사람 검수로 자동화할 수 있는 운영 과제다.
